# renovate-config

Общая политика обновлений для моих репозиториев. Подключается одной строкой:

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["github>mshykhov/renovate-config"]
}
```

## Что решает этот пресет

Только то, что не зависит от проекта - тип обновления:

| Тип | Поведение |
|---|---|
| `digest` / `pin` | автомерж |
| `patch` | автомерж, выдержка 14 дней |
| `minor` | PR, мерж руками |
| `major` | PR только после галочки в Dependency Dashboard, автомержа нет никогда |

Автомерж происходит ночью (01:00-05:00 UTC): плохое обновление не должно приезжать в рабочее
время, особенно там, где мерж означает деплой.

Выдержка перед автомержем больше глобальной (14 дней против 7) намеренно. Автомерженный релиз -
это релиз, который никто не прочитал перед выкатом, и две недели дают времени снять с реестра
скомпрометированный пакет.

## Чего он НЕ решает

Имён пакетов здесь нет и не будет. Список вида «longhorn, vault, cnpg - руками» осмыслен только
там, где известно, что за этими именами стоит; в чужом репозитории он либо бесполезен, либо
опасен. Поэтому:

- **Ужесточение** (не автомержить своё stateful - БД, storage, операторы с состоянием, CRD) -
  правило `automerge: false` в самом репозитории.
- **Ослабление** (автомержить minor у stateless-компонентов) - правило `automerge: true` там же.

Правила репозитория идут после подключённого пресета и поэтому перекрывают его.

## Пример: репозиторий поверх пресета

```json
{
  "extends": ["github>mshykhov/renovate-config"],
  "packageRules": [
    {
      "description": "Stateless: падение чинится откатом коммита.",
      "matchUpdateTypes": ["minor"],
      "matchDepNames": ["traefik", "external-dns", "cert-manager"],
      "automerge": true
    },
    {
      "description": "Данные: плохой апгрейд уносит их с собой.",
      "matchDepNames": ["longhorn", "cloudnative-pg", "vault"],
      "automerge": false
    }
  ]
}
```

## Обязательное условие

Renovate автомержит только по зелёным проверкам. В репозитории без CI автомерж не доказывает
ничего - сначала проверки, потом этот пресет.
